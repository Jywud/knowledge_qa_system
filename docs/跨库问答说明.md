# 默认跨授权知识库问答

员工直接输入问题即可提问，默认范围为“全部可访问知识库”。输入框左下角可选限定某一个库；没有授权或所选范围没有可用文档时不能发送。

## 范围与权限

角色决定可读库的并集，会话记录创建时的范围快照。范围在会话创建后固定，后续新增的授权库不会自动混入旧对话；新建会话可以使用最新范围。

所有快照内的库必须仍然存在且全部有权访问，才能读取会话历史、标题、来源或继续提问。撤回其中一个库会隐藏整条跨库会话，避免旧答案/摘要中的其他库信息泄漏；在途任务会停止，旧模型记忆不再复用。重新完整授权后可查看历史，作废的记忆仍不恢复。

向量、BM25 与异常降级都同时过滤当前角色授权、会话快照和可选单库。客户端不能传入额外的范围 ID。没有认证用户时内部检索直接拒绝。引用显示库名和文档名，同名文档不会合并；模型遇到资料矛盾时按来源分别说明。

有关联跨库会话的知识库删除返回409。会话所有者可以删除自己的会话，即使该会话已失去部分库权限；管理员不会因此获得查看或删除他人会话的能力。

## 本地结构更新

已确认允许更新本地开发数据库。新增 `conversations.kb_scope TEXT NULL` 和 `chat_scope_v1` 标记；不改变知识库、用户、角色、授权、文件、分块、向量及原文件，不清理既有单库会话。

停止后端并备份数据库/实际上传目录，然后从根目录运行：

```powershell
backend/.venv/Scripts/python.exe -B backend/scripts/migrate_chat_scope.py --plan
backend/.venv/Scripts/python.exe -B backend/scripts/migrate_chat_scope.py --apply
```

旧库需先有 roles_v1 标记；未完成会明确阻止。迁移的字段和标记在同一事务，失败回滚；重复执行不重置快照或记忆。新安装在启动事务中直接创建结构和两个标记，无需运行迁移命令。

回退应停止后端并使用更新前完整备份恢复数据库，运行匹配代码；不要手工清除标记。

## 验证

后端覆盖跨库创建、范围固定、撤权历史/在途流、无授权拒绝、降级检索与快照取交集、跨库引用身份、删除约束及事务迁移。隔离PostgreSQL实测真实向量权限与ANY数组范围过滤。

浏览器使用两个授权示例库和第三个未授权示例库验证默认跨库、单库限定、来源原文和撤权；示例账号、角色、文档与状态在验收后清理。具体结果补充于本轮执行计划。
