# M0 稳定化第 1～4 项执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task. 当前会话实施，独立代理审查计划和结果；不自动提交或推送。

**Goal:** 修复空库历史打不开、会话知识库校验缺失、流式问答错误被吞，以及新增账号/重置密码规则不一致。

**Architecture:** 沿用 FastAPI、SQLAlchemy、Vue 3 和现有接口。历史读取与问答资格解耦；问答在持久化消息和调用模型前校验知识库；前端统一收敛创建会话和流式请求的失败；账号规则通过后端共用函数及前端共用校验器实现。不新增依赖、外部服务或数据库迁移。

**Tech Stack:** 现有 Python/pytest/SQLite、Vue、Node 内置 node:test/vm，无额外测试框架。

## 范围与兼容策略

- 历史读取只校验会话归属，不依赖知识库、分块是否存在；他人会话继续返回 404。
- 新会话必须携带正整数知识库 ID，缺失/非正值返回中文 400，不存在返回 404。允许创建空库会话，但空库不得继续问答。
- 旧会话未绑定时可通过本次 `ChatRequest.kb_id` 绑定一次；已绑定时拒绝更换知识库。问答还须检查非空问题及知识库存在可用分块。
- 校验失败不修改标题/绑定、不保存用户消息、不调用模型。知识库读取可用共享行锁，避免与删除并发时在校验后产生外键冲突。当前全员共享访问保持现状，M1 再接入成员权限。
- 新增用户名去首尾空白后须为 1～64 个字符，支持现有中文用户名；不得是空白。新密码 6～128 个字符且不得全为空白，保留密码中的合法空格、不自动 trim。三个写密码入口（新增/管理员重置/个人改密）采用同一规则。
- 登录不新增密码最短长度限制，已有短密码账号仍可登录；不修改已有用户名、密码或默认启动种子账号。
- HTTP 401 清理凭证并跳登录；403/429/400/404/5xx 显示可读原因。无论会话创建失败、流式请求失败还是断网，均恢复发送状态；创建失败保留输入，不留下空白助手回复。
- 只处理 M0-1～4，不扩展为权限模型、索引/分页、引用版本、任务队列、全局认证重构。
