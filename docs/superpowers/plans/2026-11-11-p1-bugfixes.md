# P1 缺陷修复执行计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. 本次由当前会话执行，独立代理审查计划和最终代码；不自动提交、推送。

**Goal:** 修复文件更新丢数据、删除操作外键冲突导致 500、改密后旧令牌仍有效这三类 P1 问题。

**Architecture:** 保持 FastAPI + SQLAlchemy + 现有后台处理流程，不引入依赖、外部服务、数据库字段或迁移。文件更新先保存到独立临时目录，旧分块在替换事务提交前始终可读；删除关联数据采用拒绝删除并返回 409；JWT 增加由当前密码哈希和现有 JWT 密钥计算的 HMAC 密码版本。

**Tech Stack:** Python、FastAPI、SQLAlchemy async、现有 SQLite 测试依赖、pytest、标准库 tempfile/uuid/hmac。

## 范围与决策

- 仅修复上述三个 P1；其他 P2、界面重构、任务队列、软删除与部门权限不在本次范围。
- 不修改 `.env`、密钥、生产配置、现有真实数据库或真实上传文件；测试全部使用临时目录和内存 SQLite，不调用真实模型。
- 保留已有三个未跟踪二阶段文档，不修改它们。
- 有会话引用的知识库、有知识库/上传文件/会话/审计引用的用户拒绝删除，返回中文 409；无关联数据仍可正常删除。此方案保留历史及审计，不隐式级联删除他人数据。
- 首次部署后，缺少密码版本的历史 JWT 必须重新登录；之后个人改密和管理员重置（包括重置为相同明文）都会使原令牌失效。
- 文件更新失败时保留旧文件、旧分块和旧版本号；若旧分块可用，恢复 `ready` 并在 `status_message` 说明更新失败。首次上传失败的行为保持不变。
- 当前没有任务持久化，进程异常退出可能留下临时文件；本次保证旧版本可用，不扩大为任务系统改造。

## Task 1：测试隔离与文件更新数据保护

- [x] **1.1 建立测试隔离。** `test_db` 通过 SQLAlchemy connect 事件执行 `PRAGMA foreign_keys=ON`，先提交用户再提交知识库；yield 会话工厂。将后台 `app.database.SessionLocal` 和上传目录指向同一个内存库和 pytest 临时目录。
- [x] **1.2 添加失败测试并确认红灯。** 覆盖同名超限 413 后原文件/分块/版本不变；新文件解析或 Embedding 失败后旧内容保留；更新为空文件不得替换旧版本；成功前仍能读到旧分块；成功后只存在新分块且版本加一。
- [x] **1.3 实现更新暂存。** `update_file` 读取并锁定文件行，检查 `processing`，使用 `uploads/.pending/<uuid>.<ext>` 保存上传；保存失败删除临时残片。只提交 `processing` 状态，不提前更改文件名、大小、版本或删除旧分块。请求提交失败时 rollback 原会话，以新会话锁行，并用版本/状态/本次写入的 `updated_at` 一起确认归属；确认属于本次请求时恢复旧状态，核实成功后清理暂存，无法核实时保留暂存并记录错误，避免永久卡住 processing 或覆盖其他请求。
- [x] **1.4 实现事务替换。** 新增 `process_file_update(file_id, path, file_type, filename, size, expected_version)`。锁定文件行并确认版本/状态；在同一个事务删除旧分块、调用现有 `ingest_file`、拒绝零分块及向量数量不匹配、将暂存文件重命名为 `uploads/.versions/<id>_v<新版本>_<文件名>`、更新文件元数据并提交。新目录与遗留根目录文件隔离，避免旧文件名恰为 `v2_notes.md` 时路径碰撞。异常后先由新会话锁行核实已提交版本：若新版本已生效，保留新文件；若仍是原版本，在锁内清理本次新文件并恢复旧状态；若无法核实，保留两份文件并记录错误，不能猜测性删除。成功后仅清理事务内预先记录的旧文件路径，避免误删后续并发更新产生的新版本；清理失败不能把已成功提交的版本标记为失败。
- [x] **1.5 补齐兼容与边界。** `reindex_missing_embeddings` 优先使用 `.versions` 中当前版本精确路径，兼容旧 `<id>_<filename>` 路径，不任取历史 glob 首项；文件/知识库删除同时清理根目录和 `.versions` 对应文件，文件删除也锁行，避免与更新互相覆盖。测试向量失败、空文件、磁盘切换失败、提交前失败、实际提交成功后抛异常、遗留文件名碰撞及暂存文件清理。若进程在切换前异常退出，旧文件及已提交旧分块仍保留。
- [x] **1.6 确认绿灯。** 运行 `tests/test_files.py` 和 `tests/test_file_updates.py`，检查现有上传功能未回归。
- [x] **1.7 前端状态联动。** 文件更新提交提示改为“已提交更新，正在后台解析”，不提前声称版本已升级；`ready` 且有更新失败消息时显示警告标签和 tooltip，让保留旧内容的失败状态可见。

## Task 3：改密后立即撤销旧令牌

- [x] **3.1 添加失败测试并确认红灯。** 个人改密后旧 token 为 401，新密码登录后的 token 为 200；管理员重置另一个账号后原 token 为 401，管理员 token 仍有效；重置相同明文也撤销旧 token；拒绝没有版本的历史 token 和非字符串版本、异常 `sub`。
- [x] **3.2 最小实现。** 在 `auth.py` 增加私有密码版本函数：`HMAC-SHA256(jwt_secret, 'password-version:' + password_hash)`，使用标准库及现有密钥，不泄露原哈希。`create_token` 加入 `pwd_ver` 字段，鉴权要求 `sub/exp/pwd_ver`，读取当前用户后以 `hmac.compare_digest` 比较版本，缺失/不符/格式异常统一 401。现有两个改密入口已经重新生成带随机盐的哈希，无需修改表结构。
- [x] **3.3 确认绿灯。** 运行 `tests/test_auth.py` 和 `tests/test_users.py`，确认登录、角色权限、防暴力破解仍有效。
