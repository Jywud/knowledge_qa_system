# 在线向量模型配置设计

## 背景

当前系统默认使用本地 Ollama 的 `bge-m3`。部分企业环境希望使用阿里云百炼等在线 Embedding 服务，因此需要支持通过 `.env` 切换，不改业务代码。

## 方案

新增 `EMBED_PROVIDER` 配置：

- `ollama`：默认，继续使用 `OLLAMA_BASE_URL` + `EMBED_MODEL`
- `openai`：使用 OpenAI 兼容协议在线服务，通过 `EMBED_OPENAI_BASE_URL` 指定供应商

阿里云百炼的兼容地址：

```env
EMBED_PROVIDER=openai
EMBED_MODEL=text-embedding-v3
EMBED_OPENAI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBED_OPENAI_API_KEY=your-dashscope-api-key
EMBED_OPENAI_DIMENSIONS=1024
EMBED_DIM=1024
```

## 约束

1. `EMBED_DIM` 必须与在线模型输出维度一致。
2. 已有 chunk 的向量维度由 PostgreSQL `chunks.embedding` 列决定；切换不同维度模型时，需要清空并重建向量数据。
3. 相同文本不能用不同模型重复计算后混存，否则检索结果不可信。
4. 不新增依赖，继续复用已有 `langchain-openai`。

## 实现点

1. `config.py` 增加供应商、兼容地址、API Key 和输出维度配置。
2. `document_service.get_embeddings()` 根据 `EMBED_PROVIDER` 返回：
   - `OllamaEmbeddings`
   - `OpenAIEmbeddings`
3. 上传入库、启动补向量、问答检索统一继续调用 `get_embeddings()`，业务层不感知具体供应商。

## 验证

1. 默认 `EMBED_PROVIDER=ollama` 时，现有行为不变。
2. 切换 `EMBED_PROVIDER=openai` 且未配置 Key 时，上传和检索应给出明确错误。
3. 配置阿里云百炼后，上传文件能完成向量化，问答能命中来源。
