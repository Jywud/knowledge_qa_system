# 设计文档

版本：v1.2（2026-10-26）　多知识库改造 + 混合检索

## 1. 技术栈

| 层次 | 选型 |
|---|---|
| 前端 | Vite + Vue 3 + Element Plus |
| 后端 | Python 3.13 + FastAPI（本地虚拟环境 `.venv`） |
| 编排 | LangChain 1.x / LangGraph |
| 对话记忆 | LangGraph Postgres Checkpoint（持久化，按会话隔离） |
| 向量库 | ChromaDB（本地持久化，进程内运行） |
| 关系库 | PostgreSQL 16（Docker 容器 `my-postgres`，库 `knowledge_qa`） |
| Embedding | Ollama 本地 `bge-m3` |
| 对话大模型 | 火山方舟 Ark（OpenAI 兼容协议）`deepseek-v4.1-flash` |

## 3. 数据模型

```
users(id, username 唯一, role[user|admin], password_hash, created_at)
knowledge_bases(id, name 唯一, description, created_by→users, created_at)
files(id, kb_id→knowledge_bases, filename, file_type, size, version, status, uploaded_by→users, created_at, updated_at)
chunks(id, file_id→files 级联, chunk_index, page_no, content)
conversations(id, user_id→users, title, kb_id→knowledge_bases 可空[null=全部], created_at)
messages(id, conversation_id→conversations 级联, role[user|assistant], content, sources JSON, created_at)

Chroma collection "knowledge"：
  id = "{file_id}_{chunk_index}"
  metadata = { kb_id, file_id, chunk_index, source, page }
  向量 = bge-m3 (1024 维)
```

检索来源元数据从 PostgreSQL 补全：`file_type`、`kb_name`、`uploaded_at`。

## 4. 核心流程

### 4.1 文件入库

```
上传 → 校验类型 → 保存 uploads/{file_id}_{filename}
     → LangChain Loader 解析（TextLoader/Docx2txtLoader/PyMuPDFLoader）
     → RecursiveCharacterTextSplitter(800/100) 切分
     → 分块写 chunks 表 + bge-m3 向量化写 Chroma（metadata 带 kb_id）
```

### 4.2 问答

```
POST /api/conversations/{id}/chat（SSE）
→ 取会话最后一条消息 → 混合检索 Top-K（system_settings.top_k）
   向量通道：Chroma similarity_search，candidate_k = max(TopK * 2, 10)
   关键词通道：PostgreSQL chunks 表 BM25，candidate_k = max(TopK * 2, 10)
   融合排序：RRF = Σ 1 / (60 + rank)
   元数据补全：file_type / kb_name / uploaded_at
→ 组装系统提示词（含来源编号）+ LangGraph 历史消息
→ Ark LLM 流式生成 → SSE 逐 token 推送
→ 完成后：最终来源写入 SSE + assistant 消息镜像入 messages 表

记忆：LangGraph checkpoint，thread_id = "user-{user_id}-conv-{conversation_id}"
```

### 4.3 删除

| 对象 | 动作 |
|---|---|
| 知识库 | 遍历其文件逐一删向量/分块/物理文件 → 删 files 行 → 删 knowledge_bases 行 |
| 文件 | 删 Chroma 向量（按 id 规则）→ 删 chunks/files 行 → 删物理文件 |
| 会话 | 删 conversations 行（messages 级联）→ checkpointer.adelete_thread() 清记忆 |

## 6. 前端约定

- 全局状态集中在 `store.js`：`token`（localStorage `kqa_token`）、`user`、`conversations`、`currentConversationId`
- axios 请求拦截器自动携带 `Authorization: Bearer {token}`；响应 401 时清除凭证并跳转 `/login`
- 路由守卫：无 token 访问业务页 → `/login`；有 token 访问 `/login` → `/chat`
- 登录页 `/login` 独立于布局；其余页面嵌套在 `AppLayout`（侧栏 + 头部下拉）下
- 会话懒创建：进入页面可直接输入，首条消息发送时才创建会话
- 新增「知识库」页：卡片列表 + 搜索 + 创建/编辑/删除 + 「进入」跳转该库的文件管理
- 文件管理页顶部加知识库选择器，列表/上传按所选库过滤
- 对话输入区上方加知识库选择器（默认「全部知识库」），仅新会话首条消息时生效；侧栏会话项显示所属知识库标签
- 流式解析：fetch + ReadableStream，按 `\n\n` 分帧，`data: {type: token|sources|error|done}` 协议
- 权限显隐：`user.role === 'admin'` 控制文件管理页写操作
- 后端以 JWT 中的用户 ID 鉴权，前端不再传 `user_id`（防伪造）

## 7. 关键实现决策（与代码对齐）

1. **Windows 事件循环**：psycopg 异步仅支持 SelectorEventLoop，uvicorn 0.54 默认强制 Proactor，因此必须用 `python run.py` 启动（内含 loop_factory 指定），不要用 `uvicorn` 命令行
2. **系统代理**：Ollama 客户端已设 `trust_env: False`，避免本机代理拦截 localhost:11434
3. **轻量迁移**：建表后执行 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 兼容旧库；首个用户自动升级为 admin
4. **消息双写**：checkpoint 存对话状态用于 LLM 上下文，messages 表镜像用于列表展示，删除会话时两处都清
5. **知识库共享**：检索不做用户过滤（共享知识库的正确行为）；文件写操作在接口层校验角色
6. **认证**：PBKDF2 密码哈希（Python 标准库，无额外依赖）+ PyJWT 签发 token；旧免密账号无 password_hash 无法登录，需管理员重置密码
7. **多知识库检索**：单 Chroma collection + metadata.kb_id 过滤（不按库建多 collection，避免多 embedding 实例）；会话创建时绑定 kb_id，保证多轮记忆检索范围一致
8. **旧数据迁移**：轻量迁移建 knowledge_bases 表 + 自动创建「默认知识库」，现有 files.kb_id 空值全部挂到默认库，不丢数据
9. **混合检索**：向量通道保语义，BM25 通道使用 LangChain Community `BM25Retriever`（依赖 `rank_bm25`）保精确词；中文暂用单字 + 英数 token 的轻量分词，避免引入分词依赖。详细方案见 `docs/检索优化需求与设计.md`

## 8. 运行与配置

启动顺序：`docker start my-postgres` → Ollama（含 bge-m3）→ `cd backend && .venv\Scripts\python run.py` → `cd frontend && npm run dev`

配置项见 `backend/.env`（示例见 `.env.example`），`.env` 已被 gitignore，密钥不入库。
