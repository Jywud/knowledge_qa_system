# 设计文档

版本：v1.6（2026-11-12）　角色授权、固定跨库范围与统一输入区

## 1. 技术栈

| 层次 | 选型 |
|---|---|
| 前端 | Vite + Vue 3 + Element Plus |
| 后端 | Python 3.13 + FastAPI（本地虚拟环境 `.venv`） |
| 编排 | LangChain 1.x / LangGraph |
| 对话记忆 | LangGraph Postgres Checkpoint（持久化，按会话隔离） |
| 向量库 | pgvector（PostgreSQL 扩展，向量与 chunk 同库） |
| 关系库 | PostgreSQL 16（Docker 容器 `my-postgres`，库 `knowledge_qa`） |
| Embedding | 默认 Ollama `bge-m3`，支持 OpenAI 兼容在线模型 |
| 对话大模型 | 火山方舟 Ark（OpenAI 兼容协议）`deepseek-v4.1-flash` |

## 3. 数据模型

```
users(id, username 唯一, password_hash, created_at)
roles(id, name 唯一, description, system_key 可空唯一, created_at)
user_roles(user_id→users, role_id→roles；复合主键)
role_knowledge_bases(role_id→roles, kb_id→knowledge_bases；复合主键)
schema_migrations(version 主键, applied_at)
knowledge_bases(id, name 唯一, description, created_by→users, created_at)
files(id, kb_id→knowledge_bases, filename, file_type, size, version,
      status[processing|ready|failed], status_message, uploaded_by→users,
      created_at, updated_at)
chunks(id, file_id→files 级联, chunk_index, page_no, content,
       embedding vector(1024))
conversations(id, user_id→users, title, kb_id→knowledge_bases 可空, kb_scope JSON文本,
              memory_epoch, memory_thread_id, rbac_ready, created_at)
messages(id, conversation_id→conversations 级联, role[user|assistant],
         content, sources JSON, created_at)

pgvector：
  chunks.embedding = bge-m3 向量（1024 维）
  idx_chunks_embedding_hnsw = HNSW 索引（vector_cosine_ops）
```

检索来源元数据从 PostgreSQL 补全：`chunk_id`、`file_id`、`file_version`、`file_type`、`kb_name`、`uploaded_at`。RAG 和消息 sources 保留引用定位字段。

## 4. 核心流程

### 4.1 文件入库

```
上传 → 校验类型 → 保存 uploads/{file_id}_{filename}
     → 创建 files 记录（status=processing）并立即返回
     → FastAPI BackgroundTasks 后台解析和向量化
     → md/txt/pdf：按空行分组 + RecursiveCharacterTextSplitter；表格行优先聚合
     → docx：按标题层级分组，段内合并；表格展开为“列名=值”文本行
     → 分块写 chunks 表 + bge-m3 批量向量化写 chunks.embedding
     → 成功 status=ready；失败 status=failed，并写入 status_message
```

### 4.2 问答

```
POST /api/conversations/{id}/chat（SSE）
→ 校验会话归属、非空问题、固定范围内全部知识库权限和可用分块，校验失败不写消息
→ 提交用户消息，读取/初始化系统设置后提交释放请求连接
→ SSE 事件队列 + asyncio.create_task 后台生成，客户端断开不中断
→ 取会话最后一条消息 → 混合检索 Top-K（system_settings.top_k）
   向量通道：pgvector cosine distance，阈值由 RETRIEVAL_MIN_SCORE 控制
   关键词通道：读取权限与会话范围交集内 chunks 后构建 BM25Retriever
   融合排序：RRF = Σ 1 / (60 + rank)
   向量异常：降级为纯 BM25；向量结果为空：保持空结果并如实回答
→ 组装系统提示词（含来源编号）+ 最近 MAX_HISTORY_MESSAGES 条历史
→ Ark LLM 流式生成 → SSE 逐 token 推送
→ 完成后：短事务复核授权与epoch，原子保存assistant与完成指针；再次校验后发送来源

记忆：LangGraph checkpoint，thread_id = "rbac-v1-user-{user_id}-conv-{conversation_id}-epoch-{memory_epoch}-{随机ID}"；仅复用完成并提交的 memory_thread_id
```

后台生成只使用知识库 ID、TopK 和线程 ID 等基本值快照，不持有请求事务；标题和答案分别用独立短会话写入。引用按文件 ID/版本/文件名聚合，避免同名文件混组。

### 4.3 更新、引用与启动补齐

- 更新内容先保存到 `uploads/.pending/`，解析和向量化成功后，在事务中切换分块并递增版本；当前版本原文件可保存到 `.versions/`。失败保留旧版本，页面显示更新失败原因。这里未提供完整历史版本留存或回滚能力。
- 来源弹窗只请求 `GET /api/chunks/{chunk_id}?file_id=...&version=...`，每次打开重取并验证响应身份。版本不符返回 `410`，文件/分块删除或身份不符返回 `404`，响应禁止缓存。旧格式缺少精确定位时仅显示当时摘要，无摘要时提示无法定位。
- 启动检查缺失向量，逐文件独立提交；失败回滚并继续下一文件，旧块保留。补齐流程顶层异常记录后继续初始化；数据库和 Checkpoint 初始化失败仍会阻断启动。任务不持久化，恢复依赖后可重启重试。

### 4.4 删除

| 对象 | 动作 |
|---|---|
| 知识库 | 存在关联会话或处理中文件时返回 409；否则事务内删除关联文件/分块/知识库，提交后清理物理文件 |
| 用户 | 不能删除自己；有关联知识库、上传文件、会话或审计记录时返回 409 |
| 文件 | 删 chunks（含 pgvector 向量）→ 删 files 行 → 删物理文件 |
| 会话 | 删 conversations 行（messages 级联）→ checkpointer.adelete_thread() 清记忆 |

## 6. 前端约定

- 全局状态集中在 `store.js`：`token`（localStorage `kqa_token`）、`user`、`conversations`、`currentConversationId`
- axios 请求拦截器自动携带 `Authorization: Bearer {token}`；响应 401 时清除凭证并跳转 `/login`
- 路由守卫：无 token 访问业务页 → `/login`；有 token 访问 `/login` → `/chat`
- 登录页 `/login` 独立于布局；其余页面嵌套在 `AppLayout`（侧栏 + 头部下拉）下
- 页面组件使用 Vue Router 懒加载：`() => import(...)`，`AppLayout` 保持同步加载
- 用户菜单使用 Element Plus 图标，包含修改密码、用户管理、知识库、系统设置和退出登录
- 会话懒创建：进入页面可直接输入，首条消息发送时才创建会话
- 新增「知识库」页：卡片列表 + 搜索 + 创建/编辑/删除 + 「进入」跳转该库的文件管理
- 文件管理页顶部加知识库选择器，列表/上传按所选库过滤
- 新会话默认跨全部可访问知识库问答，也可限定单库；创建时以 `kb_scope` 固定范围。已创建会话不能换范围，旧未绑定且没有有效快照的会话不开放。读取历史需范围内全部库仍有权限，侧栏显示单库或全部范围，详见 `docs/跨库问答说明.md`。
- 来源数字角标只转换 Markdown 正文文本，代码、链接及转义文本沿用原渲染。弹窗逐项展示加载/错误/重试，快速切换后的旧响应不能覆盖当前弹窗。
- 流式解析：fetch + ReadableStream，按 `\n\n` 分帧，`data: {type: token|sources|error|done}` 协议
- 权限显隐：服务端 `user.is_admin` 控制文件管理页写操作
- 后端以 JWT 中的用户 ID 鉴权，前端不再传 `user_id`（防伪造）

## 7. 关键实现决策（与代码对齐）

1. **Windows 事件循环**：项目通过 `python run.py` 显式选择 SelectorEventLoop，满足 psycopg 异步驱动要求；该入口同时应用可信代理配置，不要绕过入口直接启动 Uvicorn。
2. **系统代理**：Ollama 客户端已设 `trust_env: False`，避免本机代理拦截 localhost:11434
3. **显式初始化**：旧库须停服备份后依次运行角色与跨库范围迁移；启动只检查标记，全新安装在同一事务创建管理员、角色与标记。
4. **消息双写**：checkpoint 存对话状态用于 LLM 上下文，messages 表镜像用于列表展示，删除会话时两处都清
5. **角色隔离**：员工多角色权限取并集，检索在SQL层过滤授权与会话范围；文件写操作仍仅系统管理员。
6. **认证**：PBKDF2 + JWT 密码版本校验，改密或重置后旧 token 失效。登录响应与前端缓存采用公开字段白名单；新密码统一校验 6～128 位且非全空白，已有短密码仍可登录。
7. **多知识库检索**：pgvector 与 BM25 的 SQL 同时过滤当前角色权限、会话范围快照及可选单库；默认跨授权范围，创建后不允许切换，也不从旧无范围会话猜测授权。
8. **保留数据**：角色初始化保留知识库、文件和向量；不保留旧共享会话与role枚举。跨库初始化仅加范围字段，保留角色系统下既有单库会话。
9. **混合检索**：向量通道保语义，BM25 通道使用 LangChain Community `BM25Retriever` 保精确词；中文暂用单字 + 英数 token 的轻量分词，避免引入分词依赖。后续规模扩大时切换 PostgreSQL 全文检索，见 `docs/关键词检索优化设计.md`
10. **异步向量化**：上传接口只保存文件和落库，解析、切分、嵌入在后台任务执行；处理中的文件禁止更新和删除；启动时遗留 processing 状态统一标记为 failed
11. **消息落库与上下文截断**：用户消息立即落库，AI 消息在流式生成完成后落库；checkpoint 保存完整 LangGraph 状态，发送给 LLM 时只取最近 20 条
12. **来源限流**：Vite/nginx 覆盖外部来源头，Uvicorn 仅信任明确代理；来源失败记录具有 TTL 和 4096 条容量上限，成功登录不清窗口预算。单进程/NAT 边界见 [登录防暴力破解设计](登录防暴力破解设计.md)。

## 8. 运行与配置

启动顺序：`docker start my-postgres` → Ollama（含 bge-m3）→ `cd backend && .venv\Scripts\python run.py` → `cd frontend && npm run dev`

配置项见 `backend/.env`（示例见 `.env.example`），`.env` 已被 gitignore，密钥不入库。

## 角色与范围补充

角色CRUD位于 `/api/roles`，用户角色调整为 `PUT /api/users/{id}/roles`，知识库授权反查为 `GET /api/knowledge-bases/{id}/roles`。这些管理接口仅系统管理员可调用。授权修改与审计同事务，使用内置管理员角色行同步最后管理员保护与生成最终提交。

撤权检查持续到生成和SSE消费均结束，静默模型与积压内容均受保护。会话所有者即使失去部分范围权限仍可删除自己的会话。详情见[角色设计](superpowers/specs/2026-11-12-role-kb-access-design.md)与[跨库问答说明](跨库问答说明.md)。
