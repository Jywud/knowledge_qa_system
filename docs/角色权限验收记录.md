## 实现范围

角色管理与知识库勾选授权、员工多角色并集、用户创建必选角色、角色调整、知识库授权角色只读查看。系统管理员仍负责账号、角色、知识库、文件和系统设置管理。

知识库、文件、分块、引用和会话接口均校验当前授权。向量和 BM25 查询在 SQL 层过滤。角色调整作废旧模型记忆，静默生成与慢客户端积压内容均受撤权监控；仅完成并提交的上下文可进入下一轮。

## 浏览器验收

使用临时员工、角色及两个非敏感示例知识库，完成后删除临时账号、关联、知识库、文件、分块、会话与 Checkpoint。

1. 管理员创建角色并只勾选示例 A；员工分配该角色后只看到 A，看不到 B 或原业务库。
2. 用户新增不选角色时明确提示“请至少选择一个角色”。
3. 员工文件页可看分块，无上传、更新、删除入口；管理菜单和管理路由不能访问。
4. 真实模型提问“年度培训统一在周几几点进行？”，返回“周五15点”，来源为示例 A，引用弹窗原文与分块版本一致。
5. 管理员撤回 A 授权后，再次提问返回无访问权限；会话列表清空，知识库选择清除。已显示内容不能从浏览器撤回。
