# 登录防暴力破解设计

## 目标

防止攻击者通过反复尝试密码猜测用户凭据。

## 方案

在登录接口增加内存计数器（不依赖额外表或 Redis）：

- 同一客户端 IP 在 15 分钟窗口内累计失败 5 次后，限制该来源登录 15 分钟，不对用户名设置全局硬锁。
- 锁定期间返回 HTTP 429 与中文提示。
- 登录成功不清除窗口内失败预算，避免用一个已知账号清空对其他账号的猜密计数。
- 计数器记录失败次数、过期时间、锁定截止时间；请求到来时清理过期记录。最多保留 4096 个来源，达到上限时淘汰最早使用的记录。
- Vite 和 nginx 覆盖客户端提交的 `X-Forwarded-For`，只传递实际连接来源。后端通过 Uvicorn 只信任 `TRUSTED_PROXY_IPS` 中的地址，其他来源的转发头不生效。

## 局限

单进程内存计数器，重启会清空，多进程/多实例不共享计数；大量独立来源超过容量时可能淘汰旧记录，不能替代网关层分布式防护。同一公网 NAT 地址共享额度。后续横向扩展时需统一限流存储。

默认本地入口仅信任 loopback 代理；因此本机进程可以提交代理头，符合本地开发的信任边界。其他部署不得将可信代理设置为 `*`，也不能直接信任用户提供的转发链。已有额外反向代理时需按实际拓扑配置可信地址及边缘头覆盖。

## 配置

通过环境变量控制（写入 `backend/.env`）：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `LOGIN_MAX_ATTEMPTS` | `5` | 窗口内最大失败次数 |
| `LOGIN_LOCK_MINUTES` | `15` | 锁定时长（分钟） |
| `TRUSTED_PROXY_IPS` | `127.0.0.1,::1` | 逗号分隔的可信代理地址，由 run.py 传给 Uvicorn |

Docker Compose 使用独立 `proxy_net`，前端固定地址与后端信任配置使用同一个 `QA_PROXY_IP`（默认 `172.30.250.3`），后端不发布宿主机端口。若默认代理网段与已有网络冲突，在项目根 `.env` 同时设置 `QA_PROXY_SUBNET` 和该子网内的 `QA_PROXY_IP`，例如 `172.29.240.0/24` 与 `172.29.240.3`，然后重建服务网络。不会修改或删除已有数据卷。
