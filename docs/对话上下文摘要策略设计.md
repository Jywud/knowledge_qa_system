# 对话上下文摘要策略设计

## 背景

当前对话上下文采用简单截断策略：`chat_node` 只取最近 `MAX_HISTORY_MESSAGES=20` 条消息传给 LLM，更早的消息直接丢弃。长对话中用户无法引用早期内容，回答连贯性会明显下降。

本设计引入"系统提示 + 摘要 + 最近 N 条"策略，在不大幅增加 token 成本的前提下保留长对话的关键信息。

## 目标

- 超过阈值时自动将旧消息压缩为摘要，追加到 LLM 输入
- 摘要采用增量合并方式，每次只处理新增的旧消息，不重复摘要
- 摘要生成失败时降级为当前的纯截断行为，不阻塞对话
- 不改变前端交互，不需要数据库表结构变更（摘要存在 LangGraph checkpoint 中）

## 配置项

在 `backend/app/config.py` 和 `backend/.env.example` 中新增：

| 环境变量 | 默认值 | 说明 |
|---------|--------|------|
| `SUMMARY_TRIGGER_MESSAGES` | 30 | 总消息数达到此值后开始触发摘要 |
| `SUMMARY_BATCH_SIZE` | 10 | 每次摘要处理的旧消息条数 |

`MAX_HISTORY_MESSAGES=20` 保持不变。

## 触发逻辑

LangGraph 状态新增两个字段：

```python
class ChatState(TypedDict):
    messages: Annotated[list, add_messages]
    sources: list
    kb_id: str | None
    top_k: int | None
    summary: str
    summarized_count: int
```

每个会话独立维护这两个字段（由 LangGraph checkpointer 持久化）。

在 `chat` 节点前新增 `summarize` 节点：

```
START → summarize → chat
```

`summarize` 节点逻辑：

```python
messages = state["messages"]
summarized_count = state.get("summarized_count", 0)
recent_n = settings.max_history_messages

# 待摘要的旧消息：已覆盖部分之后、最近 N 条之前
old_messages = messages[summarized_count:-recent_n]

if len(old_messages) < settings.summary_batch_size:
    return {}

old_summary = state.get("summary", "")
new_summary = await summary_llm.ainvoke(summary_prompt(old_summary, old_messages))

return {
    "summary": new_summary,
    "summarized_count": summarized_count + len(old_messages),
}
```

### 触发示例

| 总消息数 | summarized_count | 旧消息范围 | 动作 |
|---------|-----------------|-----------|------|
| 20 | 0 | messages[0:0] = 空 | 跳过 |
| 25 | 0 | messages[0:5] = 5 条 | 不够 10 条，跳过 |
| 30 | 0 | messages[0:10] = 10 条 | 触发，摘要第 1~10 条 |
| 35 | 10 | messages[10:15] = 5 条 | 不够 10 条，跳过 |
| 50 | 10 | messages[10:30] = 20 条 | 触发，摘要第 11~30 条 |

如果用户短时间内连续提问导致 old_messages 超过 batch_size，一次性全部摘要，减少 LLM 调用次数。

## 摘要 Prompt

使用与聊天相同的 LLM，但非流式调用（streaming=False），避免摘要 token 混入聊天的 SSE 流。

```
请将以下对话压缩为一段简洁摘要（不超过 200 字），保留：
- 用户的核心目标和意图
- 已确认的关键事实
- 已完成的操作或决定
- 待解决的问题
- 用户明确表达的偏好

已有摘要（如果有，请在此基础上合并新对话的要点）：
{old_summary}

新对话内容：
{new_messages}

请直接输出摘要内容，不要加任何前缀或解释。
```

## chat 节点改动

chat_node 中构建消息列表时插入摘要：

```python
system = SystemMessage(content=RAG_SYSTEM_PROMPT.format(context=context))
summary = state.get("summary", "")
if summary:
    summary_msg = SystemMessage(content=f"以下是本次对话前期的摘要：\n{summary}")
    history = state["messages"][-max_history:] if max_history > 0 else state["messages"]
    response = await llm.ainvoke([system, summary_msg, *history])
else:
    response = await llm.ainvoke([system, *history])
```

## 失败降级

summarize 节点内的 LLM 调用如果抛出异常，捕获异常并返回空 dict，跳过本次摘要。对话继续使用当前的截断行为。

## 测试计划

1. 消息数小于阈值时不触发摘要，summary 为空
2. 消息数达到阈值且旧消息数量达标时触发摘要，summary 非空且 summarized_count 更新
3. 摘要 LLM 调用失败时返回空 dict，不影响 chat 节点执行
4. chat_node 中有摘要时消息列表包含摘要 SystemMessage
